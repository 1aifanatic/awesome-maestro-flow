# Security Policy

The security of the community is important. This repository is a curated list of links — it does not contain application code — but security issues can still arise. Examples include:

- malicious links
- suspicious projects
- credential leaks (tokens, keys, or passwords in submitted content or linked repositories)
- compromised repositories linked from this list
- other security problems

## Reporting a Security Issue

**Do not publicly disclose security vulnerabilities in issues or pull requests.**

Instead, report security concerns privately to the maintainers.

> [!NOTE]
> A dedicated security contact will be added here when available. Until then, report privately to the current maintainers (see the Maintainers section of README.md) — without including sensitive details in public issues.

## What to Include in a Report

When reporting, please include:

- A description of the issue
- The affected URL or project
- Steps to reproduce or verify, if applicable
- Any suggested remediation

## Handling Process

1. A maintainer acknowledges the report.
2. The issue is investigated.
3. If the reported content is malicious, compromised, or leaks credentials, the link or project is removed from the list as soon as possible and reported as appropriate.
4. The reporter is updated when the issue is resolved.

## Policy for Linked Projects

This repository only links to external projects. If a linked repository is compromised or becomes malicious, please report it and the link will be removed as soon as possible. We cannot fix issues inside external repositories — contact their maintainers for that.
